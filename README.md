# 混元翻译工作台 · HY-MT Translator

全本地、离线运行的文档翻译工作台。底层用 [llama.cpp](https://github.com/ggml-org/llama.cpp) 跑腾讯混元的
**HY-MT1.5-7B**（GGUF 量化），外面套一层自己写的本地 Web 界面：拖进去一批文件、点一下开始，
译文就按你要的位置和命名写回磁盘 —— 不联网、不上传、不花钱。

> 单张 8GB 显卡上实测约 **67 tok/s**（CUDA + Q4_K_M），一篇 6700 字的中文长文约 40 秒翻完。

## 功能

**翻译**
- **38 个语种**互译（中文/英语/日语/韩语/法语/德语/俄语/西班牙语/阿拉伯语/藏语/维吾尔语/哈萨克语/蒙古语/粤语……），源语言可留「自动识别」
- **6 种格式**：`txt` `md` `docx` `pdf` `epub` `srt` `lrc`
  - DOCX 复制后原地替换段落文本，**样式、图片、页眉页脚、表格全部保留**
  - SRT / LRC **保留时间轴**，只翻字幕和歌词本身
  - EPUB 按 OPF 顺序逐章改写 XHTML，整包重建
  - PDF 抽取文本层后转 DOCX/TXT（含分栏排序与断词还原）
- 长文按句子切块，并把上一块原文作为上下文传给下一块，避免前后称呼/术语漂移
- 术语表强制对照（`原文 = 译文`，每行一条）

**批量与导入**
- 队列批量翻译，逐文件显示进度、字数、速度、剩余时间
- 导入方式三种：拖文件、**拖整个文件夹**、点「选择文件夹」→ 扫描预览 → **确认导入**
  - 选文件夹导入的是磁盘真实路径，文件不进 `uploads`，几百个也是秒进队列
  - 递归子目录，自动排除 `~$` 锁文件、`.git`/`node_modules`/回收站等
- 单次上限 400 个文件；不同子目录同名文件自动加 `(2)(3)` 后缀，不会互相覆盖

**输出**
- 输出位置三选一：**统一目录（按日期）** / **源文件同目录** / **自定义目录**
- 可选是否在文件名上加「译文」后缀（默认加）
- 点每行的 ↗：在资源管理器里**选中并高亮译文**，窗口临时置顶 6 秒，不用自己翻目录
- 中途停止也会把已翻好的部分写出来，不会丢

**监控**
- 顶栏实时显示显存、GPU 使用率、功耗、频率、温度，负载高时胶囊变橙
- 每篇翻完给出**平均 tok/s**，队列汇总显示整批的总速度

## 目录结构

```
app/
  server.py      本地 HTTP 服务：静态页、上传、任务提交、SSE 进度推送
  engine.py      llama-server 子进程托管、38 语种表、官方提示词模板、长文切块
  pipeline.py    6 种格式的解析 / 分段 / 翻译 / 回写，输出路径与命名规则
  jobs.py        任务队列、逐文件进度与统计
  fspick.py      系统「选择文件夹」对话框（纯 ctypes，不依赖 tkinter/pywin32）
  shellopen.py   explorer 定位文件 + 窗口置顶
  web/           前端（原生 HTML/CSS/JS，无框架、无构建）
_install/        开发期的测试与打包脚本
示例文件/         可直接拖进去试翻的样例（txt/srt/lrc/docx/pdf/epub）
使用说明.md       详细使用文档：每个选项是什么意思、常见问题怎么解
```

后端只用标准库的 `http.server`，不引框架；前端零依赖，改完刷新就生效。

## 快速开始

1. **Python 3.10+**（开发环境用的是 3.13），装依赖：
   ```bash
   pip install -r requirements.txt
   ```
2. **模型**：把 GGUF 放到 `models/HY-MT1.5-7B-Q4_K_M.gguf`
   （在 Hugging Face / ModelScope 搜 `HY-MT1.5-7B GGUF`，选 `Q4_K_M` 量化；国内可用 hf-mirror 镜像）
3. **推理运行时**：从 llama.cpp 的 Releases 下载 Windows 预编译包，解压出 `llama-server.exe` 及同目录 dll
   - `runtime/llama/` —— CPU / Vulkan 版
   - `runtime/llama-cuda/` —— CUDA 版（有 N 卡优先用这个，比 Vulkan 快约 5～6 倍）
4. 启动：双击 `启动混元翻译.vbs`（无窗口），或 `python app/server.py --open`
5. 界面打开在 <http://127.0.0.1:18081>

首次翻译才会把模型加载进显存（10～30 秒），之后一直复用。

## 配置

`app/config.json` 首次运行自动生成，界面上的选择会自动存回去。常改的几个：

| 键 | 说明 |
| --- | --- |
| `backend` | `auto` / `cuda` / `vulkan` / `cpu`，显存不够会自动回落 |
| `ctx` | 上下文长度，默认 8192 |
| `ngl` | 卸载到 GPU 的层数，99 = 全部 |
| `out_dir_mode` | `app`（统一目录）/ `source`（源文件同目录）/ `custom`（自定义） |
| `rename_output` | 译文文件名是否加「译文」后缀 |

## 已知限制

- **仅 Windows**：用了资源管理器定位、Shell 文件夹对话框、ctypes 调 user32
- 8GB 显存下 Q4_K_M + ctx 8192 约吃 7.4GB，余量很小；再大就得降 `ctx` 或换 Vulkan/CPU
- PDF 只能抽文本层，**不还原原版式**（输出 DOCX/TXT）；扫描件需要先 OCR
- 队列串行翻译，暂不支持多卡/并发多篇
